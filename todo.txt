# MASTER PROMPT: Universal GitHub Project Installer & Local Development Manager

Act as a Senior Flutter Desktop Developer, DevOps Architect, Systems Engineer, and AI Software Engineer.

Build a production-ready, open-source desktop application for Windows and macOS using Flutter.

## 1. Product Concept

The application will allow any user to install and run software directly from GitHub without manually configuring development environments.

The workflow:

1. User installs our desktop application.
2. User opens the application.
3. User pastes a GitHub repository URL.
4. Application analyzes the repository.
5. Automatically detects the programming language and framework.
6. Detects required runtime, dependencies, database, and environment variables.
7. Installs and configures everything.
8. Runs the application locally.
9. Allows the user to access the running application through a browser.
10. Optionally exposes the local application through a public tunnel URL.

The application must support managing multiple GitHub projects from one dashboard.

## 6. Automatic Project Configuration

Create an intelligent installation engine.

It must:

- Read README documentation.
- Analyze configuration files.
- Identify dependency managers.
- Identify database configurations.
- Identify environment variables.
- Detect available installation scripts.
- Identify startup commands.

For Laravel:
- Install Composer packages.
- Create .env where appropriate.
- Generate application key.
- Configure database.
- Run migrations with user approval.
- Install frontend dependencies if necessary.
- Start Laravel.

For Node.js:
- Detect package manager.
- Install packages.
- Configure .env.
- Configure database if required.
- Run migrations where appropriate.
- Start application.

For Python:
- Create virtual environment.
- Install requirements.
- Configure environment variables.
- Configure database.
- Start application.

Do not assume all projects follow standard conventions. Generate a project-specific installation plan.

Before executing arbitrary repository scripts, show the commands and obtain authorization.

## 10. Public IP / Tunnel Manager

Create a dedicated feature called:

**Expose My Project**

The user should be able to expose a locally running project to the internet.

Example:

Local application:
http://localhost:8000

Public tunnel:
https://example-tunnel.example.com

Support:

- Cloudflare Tunnel.
- Other supported tunnel providers through an extensible architecture.

Features:

1. Select an installed project.
2. Detect its local port.
3. Start the tunnel.
4. Generate or retrieve the public URL.
5. Display the public URL.
6. Copy public URL.
7. Stop tunnel.
8. Monitor tunnel status.
9. Manage multiple project tunnels.

The tunnel must only expose the selected application.

Provide warnings about authentication, sensitive data, and public access.

Do not claim to expose the user's actual router public IP unless a separate network configuration feature is implemented. A tunnel URL is a safer alternative to direct port forwarding.
